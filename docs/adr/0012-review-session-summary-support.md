# Review session summary support before storage

Session summaries remain concise prose. A second bounded model call reviews their factual support before the processor writes notes and a summary together.

The previous decoder checked shape and source membership. A valid source ID could accompany a completion claim that repeated a request instead of describing the answer. Stronger generation instructions alone did not prevent that failure.

The new internal contract is `summary-support-v1`. It reviews every nonempty summary field, including the title. The verdicts are `supported`, `unsupported`, `contradicted`, and `insufficient_context`. Fixed reason codes distinguish attribution, scope, attributes, intent and missing context. The reviewer receives original current observations and bounded same-session history with their evidence roles. The candidate cannot support itself. Historical derived records cannot override contradictory original evidence.

Each supported or contradicted field must reference exact quotes in the disclosed source bodies. Code requires each quote to occur exactly once in its named source. This avoids model-generated character offsets and preserves Unicode text. Ambiguous quotations require more context. Exact presence establishes quote ownership, not semantic relevance or truth. The reviewer remains fallible and can share the generator's bias.

The reviewer uses the same immutable execution profile as generation. It has no tools or correction callback. Generation, support reviews and the optional Jev quality gate share one monotonic execution deadline and one generation correction. Corrected candidates pass shape validation and support review again. A correction cannot remove a previously generated summary. A late negative or malformed review quarantines only the exact still-owned attempt, even after its lease expires. A replacement lease cannot be changed by the old reviewer. Malformed responses, failed calls, missing context after correction, expired leases and changed evidence prevent atomic storage. Raw work remains available. Rejected and uncertain summaries quarantine only their failed batch. The retained service can process fresh later work, including after restart, without retrying the failed batch. Malformed, unavailable, stale and unknown operational failures retain the existing project-blocking policy. Notes without a summary do not require this review.

The observation ledger adds a bounded `execution_calls` JSON column. Generation and up to two support reviews retain separate requested profiles, observed identities, outcomes and normalized metrics. Cumulative generation checkpoints replace prior snapshots. Independent token counters add once at finalization. A counter stays null when any call omits it; measured call values remain available in the detailed records. Whole-attempt elapsed time includes nested review time once. Old records remain readable and are not marked as reviewed. Stored summary shape and `verification=not_assessed` remain unchanged.

Tests can inject generation and review separately through `process_pending` and `recover_failed_batch`. An injected generator without an explicit reviewer fails closed when it produces a summary. It cannot silently open a live model process. Native fixture tests exercise correction and identity for both Codex and Pi. Deterministic verdicts test orchestration only. Independent live checks must assess useful supported output, false acceptance and unnecessary rejection, and retain every outcome.
