# Метки triage

Роль описывает состояние задачи. Строка метки является ее именем в GitHub Issues репозитория `alexandrbasis/codex-mem`. Скиллы применяют правую колонку таблицы.

| Роль upstream | Метка GitHub | Значение |
| --- | --- | --- |
| `needs-triage` | `needs-triage` | Требуется оценка сопровождающего |
| `needs-info` | `question` | Требуется дополнительная информация |
| `ready-for-agent` | `ready-for-agent` | Задача определена и готова к работе агента |
| `ready-for-human` | `ready-for-human` | Требуется работа человека |
| `wontfix` | `wontfix` | Задача отклонена |

Существующая метка `question` имеет описание `Further information is requested` и выполняет роль `needs-info`. Отдельная метка `needs-info` не нужна. Метка `wontfix` также существовала до настройки. Остальные три метки созданы при настройке и проверены чтением из GitHub.

Категории `bug` и `enhancement` используют одноименные метки GitHub. Разобранная задача получает одну категорию и одно состояние. При переходе заменяйте прежнее состояние, сохраняя остальные метки. Если одновременно стоят несколько состояний, сначала уточните выбор сопровождающего.

Обычный переход начинается с `needs-triage`. Затем задача получает `question`, `ready-for-agent`, `ready-for-human` или `wontfix`. После ответа автора задача с `question` возвращается в `needs-triage`. Прямое указание сопровождающего выполняется по правилам `triage`.

Перед изменением меток проверьте фактические имена через `gh label list --repo alexandrbasis/codex-mem`. Создавайте отсутствующую метку только в рамках разрешенной настройки. Для публикаций triage сохраняйте обязательную пометку из `triage/SKILL.md` и правила разрешений из [engineering-skills.md](engineering-skills.md).
