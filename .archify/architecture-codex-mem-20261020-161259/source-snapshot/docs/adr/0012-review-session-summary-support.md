# Review session summary support before storage

Session summaries remain concise prose. A second bounded model call reviews their factual support before the processor writes notes and a summary together.

The previous decoder checked shape and source membership. A valid source ID could accompany a completion claim that repeated a request instead of describing the answer. Stronger generation instructions alone did not prevent that failure.

The first internal contract, `summary-support-v1`, used one verdict per field and exact copied quotes. A live review accepted a false outcome attribute while citing original evidence that contradicted it. Quote ownership did not establish entailment. A bounded contrastive diagnostic was promising but failed one positive because the model copied punctuation incorrectly. Neither experiment establishes product acceptance.

The replacement contract is `summary-support-v2`. Code supplies each complete nonempty field, including the title, as an input-only unit with a stable field key. It preserves the original text and punctuation. The reviewer enumerates assertions and compares each candidate proposition with the proposition supported by evidence. Each comparison states the candidate meaning, evidence meaning, value comparison, attribution comparison, scope comparison and verdict. The verdicts remain `supported`, `unsupported`, `contradicted`, and `insufficient_context`. A supported topic cannot cover a conflicting attribute. Incomplete assertion enumeration produces uncertainty.

Code also creates contiguous source spans of at most 1,200 characters, with IDs, offsets and exact text. The reviewer selects IDs instead of copying quotes or calculating offsets. Every source retains its full disclosed parent body, role, order and current/history group. Neighboring negation, conditions and corrections remain visible. These slices are ownership units, not semantic atoms. Historical derived records cannot override contradictory original evidence, and the candidate cannot support itself.

The schema requires each field key exactly once and allows at most eight assertion comparisons per unit. Supported and contradicted comparisons need a known span. Other verdicts may have no span. Code rejects missing or unknown unit keys, unknown span IDs, invalid verdicts and exceeded bounds. Duplicate JSON keys reject in both native decoders. Mechanical field coverage does not prove that the model enumerated every assertion or interpreted it correctly. The same-profile reviewer remains fallible and can share the generator's bias.

Operational receipts retain only fixed invalid subtypes (`structure`, `unit_coverage`, `unknown_span`, `verdict`, `bounds`), status, protocol version, and candidate/evidence fingerprints. They do not save raw source or reviewer prose. Assertion-level correction feedback is bounded and treated as untrusted data, never replacement evidence. Synthetic tests can explicitly retain their own input and output.

The reviewer uses the same immutable execution profile as generation. It has no tools or correction callback. Generation, support reviews and the optional Jev quality gate share one monotonic execution deadline and one generation correction. Corrected candidates pass shape validation and support review again. A correction cannot remove a previously generated summary. A late negative or malformed review quarantines only the exact still-owned attempt, even after its lease expires. A replacement lease cannot be changed by the old reviewer. Malformed responses, failed calls, missing context after correction, expired leases and changed evidence prevent atomic storage. Raw work remains available. Rejected and uncertain summaries quarantine only their failed batch. The retained service can process fresh later work, including after restart, without retrying the failed batch. Malformed, unavailable, stale and unknown operational failures retain the existing project-blocking policy. Notes without a summary do not require this review. Routine documentation, greetings and other low-value exchanges may still be skipped under existing relevance policy. Earlier substantive accepted work still requires its summary.

The observation ledger adds a bounded `execution_calls` JSON column. Generation and up to two support reviews retain separate requested profiles, observed identities, outcomes and normalized metrics. Cumulative generation checkpoints replace prior snapshots. Independent token counters add once at finalization. A counter stays null when any call omits it; measured call values remain available in the detailed records. Whole-attempt elapsed time includes nested review time once. Old records remain readable and are not marked as reviewed. Stored summary shape and `verification=not_assessed` remain unchanged.

Tests can inject generation and review separately through `process_pending` and `recover_failed_batch`. An injected generator without an explicit reviewer fails closed when it produces a summary. It cannot silently open a live model process. Native fixture tests exercise correction and identity for both Codex and Pi. Deterministic verdicts test orchestration only. Independent live checks must assess useful supported output, false acceptance and unnecessary rejection, and retain every outcome.
