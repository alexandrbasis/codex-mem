# Стандарты разработки Codex Mem

Читайте этот документ на этапе code review. Эти правила помогают оценивать решения в коде. Требования конкретной задачи и действующий [AGENTS.md](AGENTS.md) определяют область изменения. Для UI действуют [GUI.md](GUI.md) и локальные Graphical-скиллы.

## Границы и данные

Сохраняйте разделение захвата событий, обработки наблюдений, хранения и получения контекста. Обработчик модели не должен скрыто запускаться из операции чтения. Обосновывайте новый побочный эффект в контракте вызывающей операции. Текущие границы показаны в архитектуре, на которую ссылается `AGENTS.md`.

Каждая обычная операция с памятью должна сохранять область проекта и происхождение записи. Используйте действующие правила нормализации путей из [project_scopes.py](codex_mem/project_scopes.py) и контракты [store.py](codex_mem/store.py). Проверяйте сценарий с двумя проектами, если меняется фильтрация или выбор записей.

Сохраняйте различие между исходным событием, обработанным наблюдением и производной памятью проекта. Источник подтверждает только собственные утверждения. История, частичный результат и неполные счетчики не превращаются в подтвержденное завершение или нулевое потребление.

Удаляйте секреты перед сохранением или передачей текста через действующие средства [privacy.py](codex_mem/privacy.py). Для тестов используйте вымышленные данные и временные каталоги. В репозиторий не включайте личную базу, пользовательскую историю, учетные данные и сырые диагностические квитанции.

## Реализация

Выбирайте самое узкое изменение, которое выполняет требование. Извлекайте общий модуль, когда он объединяет одно решение и скрывает детали от вызывающего кода. Само число строк, аргументов или переходов между объектами не является дефектом.

Сохраняйте явные ограничения входа, числа записей, размера ответа и времени работы на границах CLI, MCP и очереди. При изменении лимита объясните поведение на превышении. Не теряйте исходную ошибку при обработке частичного результата.

Изменения SQLite должны сохранять существующие данные и повторяемость операций после перезапуска. Проверьте миграцию с предыдущим состоянием и повтор операции, если меняется запись, очередь или восстановление. Используйте текущие транзакционные границы осознанно. Сетевой запрос или вызов модели внутри удерживаемой транзакции требует отдельного обоснования.

Базовая установка Python работает без обязательных сторонних зависимостей, как указано в [pyproject.toml](pyproject.toml). Сохраняйте загрузку необязательного semantic runtime только в соответствующих ветках. Новый обязательный пакет требует объяснения в задаче и изменения контракта установки.

## Проверка и доказательства

Проверяйте наблюдаемое поведение и границы задачи. Для исправления ошибки воспроизведите сбой и проверьте исправление. Тест, который повторяет внутренние шаги реализации, не заменяет проверку результата. Для обратимого изменения текста или настройки достаточно соразмерной проверки файлов и ссылок.

Текущий CI в [.github/workflows/test.yml](.github/workflows/test.yml) запускает следующие команды. При изменениях продукта выполняйте их из корня проекта:

```sh
python3 -m unittest discover -s tests -v
python3 scripts/acceptance.py
python3 scripts/package.py
```

Подбирайте дополнительные проверки по измененной области. Репозиторий не задает общий обязательный lint или typecheck в этом CI. Для frontend используйте реальные команды соответствующего пакета. Для engineering-скиллов используйте `python3 scripts/check_engineering_skills.py`.

Различайте локальный тест, сборку пакета, установленную версию, работающий сервис и свежее подключение MCP. Правила представления результатов и ограничения прежних проверок описаны в [docs/VERIFICATION.md](docs/VERIFICATION.md). Native-проверки с моделью расходуют учетную квоту и требуют соответствующего разрешения.

Если меняются архитектурные границы из `AGENTS.md`, обновите диаграмму и ее источники в той же задаче. Успешное сравнение хешей не подтверждает правильность описания. Review должен учитывать весь согласованный набор файлов, включая новые файлы рабочей копии.
